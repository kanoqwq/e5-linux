# SIPC 基带晚就绪后的公共网络恢复

## 已确认的问题

远航 41S 的一次正常启动中，netifd 先尝试启动 WAN，ModemManager 的
逻辑设备尚未创建，留下 `NO_DEVICE`。设备后来出现，首次注册又返回
`No network service`。此后 AT 已回报 SIM2 `CEREG=1`，但 MM 缓存仍是
enabled / idle / detached，WAN unavailable，没有默认路由。

既有恢复服务只允许在 MM 的“已注册、PS attached、有实际 RAT”同时满足时
恢复 WAN；但正常 WAN setup 本身负责启用和注册设备。开机设备晚出现的
NO_DEVICE 与这个注册前置要求形成等待缺口。不是 SIM 不存在、NV 被改坏，
也不是单纯屏幕显示错误。AT 与 MM 缓存状态不同的最初原因没有完整 URC
现场，不将它进一步归因为已证实的固件缺陷。

## 公共修复与边界

修改唯一公共入口 `openwrt/overlay/usr/libexec/e5-network-recovery`：

- 在现有 D-Bus/接口事件订阅内识别已就绪的 Unisoc 逻辑设备及有效 SIM。
- WAN 因 NO_DEVICE 不可用、仍有 autostart 意图、没有正在连接或已连接时，
  通知 netifd 恢复 availability，交给原协议脚本完成初始化、注册和拨号。
- 普通断网恢复仍要求原来的 PS/注册条件，不放宽 APN、PIN、鉴权等错误。
- 保留手动关闭数据、SIM 射频禁用、缺卡及切卡流程；不发新 AT，不新增
  定时轮询、额外服务或机型专属兜底，不改变开机回放顺序。

E5、T551M、M8、T512N、远航 41S 的构建/公共更新准备器均复制同一份服务。
逻辑没有型号判断，不在各机型另写一份。其他设备可能触发同类时序问题，
本次仅远航 41S 进行了实机部署和重启验证。

## 验证

- 公共恢复回归 14 项通过，包含晚就绪 NO_DEVICE、重复事件不重复恢复、
  禁用数据、禁用射频、PIN/缺卡、其他 modem 和注册/RAT 变化。
- 网络准备器回归 16 项通过；新增检查五款机型安装的恢复服务逐字节一致，
  启动链接和可执行权限正确。既有重试、模式设置、切卡/回放测试仍通过。
- 样机热部署后，无手动 ifup、切卡或复位射频，WAN 自动获得 IPv4/IPv6，
  外网 ping 与 DNS 查询通过，屏幕 API 显示 connected / WAN up。
- 随后再次正常重启：热点约开机 23 秒启用，WAN 约开机 60 秒连通，保留
  原 SIM2，网络、热点及 SIM 配置哈希不变。电脑恢复管理连接时间较晚，
  不把电脑 SSH 恢复时间当作设备首次联网时间。

热点的原名称在本次私有 RAM→内置安装中变为默认 E5-Linux；当前启动日志
证明它确实自动启用。按用户要求，不改正式安装器与公共热点初始化逻辑。
没有新增热点轮询/自动强开功能，也没有覆盖用户的热点开关选择。

原始回执保存在忽略目录 `out/yuanhang41s/acceptance/`，含设备私有信息，
不提交原始内容。
