# 远航 41S：SIPA 完成错误与溢出分型

2026-10-20，P720S11，SIM2 数据接口 `sipa_eth8`；代码基线

## 已确认的含义和实机证据

`sipa_priv.h` 与实际 FIFO 中断位定义一致：

| 事件 | 含义 |
| --- | --- |
| `0x10000` | TX 完成项的 error-code 中断 |
| `0x20000` | TX FIFO overflow |
| `0x40000` | TX FIFO full |

旧回调把三者统称为 `sipa overflow`，并全部累加 `no_free_cnt`。这会把已完成
但被拒绝的包误诊为额度耗尽。`ep:1` 表示 AP 端点，不表示 SIM1。

短时动态核验取自本机实际模块，临时探针在结束时全部撤除：

- 自然出现的错误项：长度 163，IPv6 UDP，546 → 547，目的为
  `ff02::1:2`，完成项 `err_code=2`，netid=8，src=25、dst=6。
- 三组受控 DHCPv6 Information Request，每组 3 个、长度 66：硬件发送校验和
  开启、临时关闭、恢复开启时均返回错误码 2。关闭卸载未消除错误，不能据此
  把它归因于硬件校验和；对照结束恢复原功能，没有永久关闭卸载。
- 每组结束都能回收发送缓冲，`left_cnt=4096`、发送链表为空，未观察到 FIFO
  流控或额度泄漏。不能由此证明所有负载/固件都没有其他 SIPA 问题。
- 当前 IPv6 RA 的 Managed/Other 均为 0；正常获得地址、默认路由和用于 LAN
  的 /64 前缀。对两个公网 IPv6 DNS 的真实 UDP 查询均收到有效应答，IPv4、
  IPv6 外网探测也通过。DHCPv6 组播拒绝不等于整个 IPv6 或蜂窝链路中断。

错误码 2 的固件正式名称尚未通过本机固件逆向确认；这里只能确认上述具体
报文与完成错误的对应，不能笼统将所有 code=2 解释成同一种协议/校验错误。

## 已修复的公共代码缺陷

1. raw-IP 包需要补 14 字节占位头时，原代码直接 `skb_push`，会将未初始化的
   headroom 交给硬件。本机探针实际读到了变化的垃圾 EtherType。现清零占位
   MAC 字段并写入真实 EtherType；先确保可写的私有头部空间，兼容克隆 skb 和
   headroom 不足。已有真实二层头的路径保持原样。
2. FIFO full/overflow 与完成项错误分开报告、计数。仅真实容量事件累加
   `no_free_cnt`；实际拒绝的完成项累加 `completion_error_cnt`，记录 code、
   src/dst、netid、长度，避免再把它称为队列溢出。
3. 无论哪一种完成事件，均保留原有回收唤醒；有错误的完成项仍正确回收 DMA
   和 skb。没有禁用 IPv6、DHCPv6、PD 请求或正常的 SIPA 休眠、流控。

补丁位于 `devices/common/sipa-completion-events.patch`，接入现有 SIPA 补丁栈，
支持干净源码、旧补丁和当前源码的原子升级与重复准备。公共构建会取得修复，
不是只修改样机工作目录。本次 MU300 仅作源码对照，未修改其仓库或实机。
