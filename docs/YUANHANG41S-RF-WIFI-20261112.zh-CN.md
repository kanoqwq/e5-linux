# 远航41S 射频关闭及改密码后无法连接反馈

## 已确认的代码缺陷与修正

公共 `t551m-radio-restart` 使用 `set -e`。数据卡 MM disable 失败，或备用卡
CFUN=4 返回失败时，原代码跳过对应 enable / CFUN=1。命令超时并不能证明
设备没有执行关闭，因此会留下可能关闭的射频。现始终尝试配对恢复，保留
失败退出码、原 AT owner、卡槽、命令顺序及数据自动启动意图；没有增加后台
射频重置或把用户主动关闭的射频自动开启。

此路径供 E5 系列共用，不是远航41S 专用。它需要先触发重连操作，不能解释
所有“长时间运行后自行关闭”的反馈。尚无该用户固件版本、关闭前日志及实际
CFUN 回读，不能认定其现场由此导致，也不能排除界面误判、基带事件或其他原因。

SC2355 的 CHANGE_BEACON 仅更新 IE，START_AP 才完整提交 AP 配置。现有
hostapd 重载优化对 SAE 配置做完整重建，但 WPA2 密码及 PSK 文件变化仍沿用
增量更新。修正让 SC2355 在密码／安全字段或 PSK、SAE 文件摘要改变时重建
BSS，清理旧 AP 和密钥状态；普通重复 reload 和其他驱动不受此规则影响。
不改写无线 UCI，不降低带宽。更新密码会短暂中断 AP，客户端须使用新密码重连。

这是针对反馈的公共重载兼容处理，尚未在反馈机器上复现或证明是唯一根因。
它适用于使用 sprd_wlan_combo 的 E5 系列机型，不是远航41S 独立策略。

## 离线验证

- `devices/t551m/test_radio_restart.py`：14 项通过，包含关闭失败仍执行恢复、
  主卡／备用卡隔离、手动关闭射频及数据意图保留。
- `openwrt/tests/wifi-security-reload.py`：实际补丁重复应用一致；在既有 ARM64
  OpenWrt 容器用 ucode 执行实际决策，验证内联密码及 PSK 文件变化重建、
  相同配置不重建、非安全配置增量更新、其他驱动不受影响。

本轮没有实机部署或复现，不把离线用例作为硬件验收。hostapd 补丁属于受
`wifi-sae-state.py` 指纹保护的编译输入，后续发布必须重编对应 Wi-Fi APK，
不能直接复用旧 APK。本轮尚未编译固件包。
