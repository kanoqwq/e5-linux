# 短信转发正则筛选

位置：蜂窝 → 短信转发 → 正则筛选（可选）。默认关闭，页面始终展开。短信筛选只使用这一组正则规则。
规则随共用配置或对应槽位的独立配置保存，仅作用于新收到的短信；
来电提醒、电源通知和手动发送测试不经过短信筛选。

## 如何设置

号码与正文分别选择关闭、黑名单或白名单。同一项的多行规则为“或”；
号码和正文两项都必须放行才转发。旧版号码／关键词黑名单不再参与匹配，
有旧配置时页面会提示重新设置所需正则；下次保存移除弃用字段，不保留隐藏拦截。
被拦截短信只记为已处理，清空规则或重启不会补发历史短信。

- 只允许短信服务号：号码白名单填写 `^(\+86)?106[0-9]+$`。
- 不转发营销内容：正文黑名单填写 `广告|促销|退订`。
- 只转发验证码：正文白名单填写 `验证码|OTP|verification code`，可勾选忽略英文字母大小写。
- 需要整条匹配时使用 `^` 和 `$`；默认是查找任何位置的匹配。

使用设备原生 ucode 的 POSIX 扩展正则，不是 JavaScript／PCRE：
不加 `/.../` 分隔符；数字使用 `[0-9]`，不使用 `\d`；
不支持前瞻、后顾等 PCRE 特性。号码保留原始 `+` 前缀；正文完整匹配，点号可跨行。
每项最多 32 条，每条最多 512 字节。空行忽略，其他空格原样保留。
白名单至少需要一条规则；非法正则保存时显示对应项和行号，不改变旧配置。

## 实现与兼容

`forward-filter.uc` 只在保存设置或启用了正则的短信事件上调用。
两项关闭时，短信处理不启动正则子进程；没有新增定时器、AT 查询或 NR0 读者。
号码／正文通过 JSON 标准输入传递，不解释为 shell，也不把短信放到外部进程命令行。
旧客户端没有发送新字段时保留已保存规则，发送空字符串则明确清空。
直接手改配置产生非法启用规则时抑制该条转发，状态只记录错误码，不记录短信内容。

## 离线测试

- `forward-regex.py`：实际 ucode 编译和匹配，中文、多行、锚点、大小写、非法规则及边界。
- `forward-regex-fixture.sh`：真实 OpenWrt jshn、配置保存／回读、分槽隔离、事件入口、
  重复抑制、不补发被拦截短信、来电不受影响，所有投递替换为本地测试文件。
- `forward-regex-browser.py`：Playwright 模拟 RPC，页面保存／回显、草稿不被状态刷新覆盖、
  中文／英文／土耳其文、手机与桌面宽度。

测试需对应依赖（Python 3、ucode／OpenWrt 测试容器、Playwright Chromium）。
原生测试可运行 `python3 openwrt/tests/forward-regex.py`；
容器测试通过 `FORWARD_UCODE_COMMAND` 指定实际 ucode 命令前缀，源路径需只读挂载到容器同一路径。
Shell fixture 参数为生产 `sms-forward` 的路径；MU300/Pro 的 `MU300_SMS_POOL_LIB`
需指向仓库 `rootfs/overlay/opt/mu300/lib/sms-pool.sh`。不需要连接设备或发送真实短信。

本轮只完成离线回归，待用户回来做实机验收。新筛选功能暂不打包、不热部署。
