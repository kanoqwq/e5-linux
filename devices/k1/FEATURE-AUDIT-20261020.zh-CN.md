# K1 功能复核与遗漏（2026-10-20）

21:03 后更新：下面发现的三个代码/实机同步遗漏已修复并部署，结果见文末。
旧发布安装包尚未重打；本记录不表示旧包已自动获得更新。

基准为同一台 `angelcare K1 / ums9157_2h10`，原厂
`AngelCare.K1.YUAN.YD.T1.0`。本轮通过 SSH 核对物理身份、源码与实际 staging
结果及运行接口，不改配置、不切 SIM/USB、不重启、不写 NV 或重新分区。

## 确认的遗漏

### 1. 网页、屏幕的手动 USB 角色控制缺少内核接口

运行后端返回 `host_supported=0`，屏幕 `usb_role` 为 info，因此不能手动选择。
当前控制器由 `dwc3-of-simple` 与 `dwc3` 正常绑定，Type-C extcon 和
`usb_role_switch` 存在，NCM 设备模式正常。缺失的是共用 `device-usb` 需要的
`usb_role_policy` ABI，而不是已经证明硬件没有 OTG。

K1 复用的 `devices/m8/dwc3-role.h` 负责 Type-C 事件驱动的自动角色与 VBUS，
没有实现该手动策略属性。后续应对这条拓扑接入手动策略，保留自动模式、
原厂供电角色和 PM 顺序；不能仅把网页开关解禁或通过直接解绑 UDC 代替。
实际 OTG 外设枚举、供电及反复插拔仍需物理连接验证。

### 2. 当前 K1 内核尚未带上最新公共 SIPA 完成项修复

本次快照记录 17 条 `ep:1 evt=0x10000`，没有伴随内核/存储错误，WAN 仍 up。
该位表示完成项 error-code，旧驱动把它和真正 FIFO full/overflow 都记作
`sipa overflow`；不能只凭这些日志认定队列溢出或推导包被拒绝的具体原因。

实际构建源码还没有私有 raw-IP 头空间处理和 `completion_error_cnt`。
公共 `sipa.py` 已接入对应补丁，K1 正常 prepare 路径会取得；但上次仅为
电荷量计算做的内核更新没有纳入这批后续 SIPA 修改，尚需刷新整套匹配内核/模块。
本轮在 K1 源码基线上运行实际 C/ASan/UBSan 回归通过，不等于已经更新样机。
补丁不会保证消除固件对 DHCPv6 等报文的拒绝，详细边界见
[SIPA 分型记录](../../docs/SIPA-COMPLETION-20261020.zh-CN.md)。

### 3. 已完成的公共 UI 更新尚未同步至样机

逐文件比较确认只有以下相关变更未落地：

- 看板主页“关机或重启”选择弹框；当前仍为“重启设备”。
- 网页网络锁定的手动小区输入；当前仍只有已发现小区的操作入口。
- 屏幕满电电池条的边框约束；当前仍使用固定 17 px 填充。

这些源代码已有，不需要再写 K1 特殊分支。看板更新需同时带上公共语言/样式、
RPC 和 action 配套；屏幕 app.js/style.css 应作为一组部署。

现有 K1 测试安装包也早于若干已热部署修复，不包含所有最新源码；本轮没有
重打包，不能把当前样机状态等同于旧安装包。

## 修复与实机落地

随后用户要求修复，上述三处均已处理：

- 新增 `devices/m8/typec-policy.py/.h`，接入共享 UMS9620 准备路径，供
  M8/K1 使用；41S 的独立板级策略不变。控制真实 CC 模式，复用原有 Type-C
  连接事件及 DWC3 的 PHY/boost 顺序，没有伪造主机插入或强开 VBUS。只有
  用户显式切换策略时执行原有 30 ms CC 断开协商，自动插拔与启动不加等待。
- IRQ 状态采样、策略写入与 VBUS 后备工作串行，拒绝与显式策略矛盾的旧
  连接状态。实际寄存器写入失败传播错误并尝试恢复，非法选项不写寄存器。
  USB 准备器重复生成 IRQ 后仍能重入策略适配，三项原生回归通过。
- 原有 K1 源码/对象目录增量构建纳入公共 SIPA 补丁；内核、全部 234 个
  根模块和启动镜像内 45 个早期模块作为完整一组部署。未复制新的源码树。
- 主页关机/重启、手动锁小区及屏幕电池条约束，连同公共语言/样式、RPC、
  action 一共七个文件一起部署并逐项校验。主页逻辑回归通过，手动小区
  90 个浏览器用例通过；没有为验证而真的锁小区或执行关机。

写入前备份并校验当前 boot 和模块树。写入后正常重启，蜂窝取得 IP、热点、
屏幕自动恢复；234 个模块与构建逐项匹配，Android B 的完整启动镜像哈希
不变，原充电及 CPU 电压配置保持。网页后端已返回 host_supported=1，屏幕
